03 / Notes from a developing engineer

Learning is more
than getting it to run.

I'm still early in my engineering journey. These are the challenges and ideas shaping the way I want to build software—not rules I claim to have mastered.

Four ideas I'm working through

My engineering notebook.

Knowing an algorithm isn't the same as building a product.

I can study data structures and understand how an algorithm works, but putting together an entire application requires different skills: organizing code, making design decisions, testing, and improving the user experience. Bridging that gap is one of my main goals.

Debugging is a way of thinking.

When code fails, the temptation is to change things until it works. I'm learning to slow down, isolate the problem, check assumptions, and understand why a fix works. I want each bug to leave me with a clearer mental model of the program.

AI can help me code. It can't replace understanding.

I use AI tools as part of learning and problem solving, especially when I need help breaking down a task or debugging. But being able to read, question, test, and explain the resulting code matters to me. My goal is to become less dependent on suggestions as my own judgment improves.

Useful software starts with a real need.

I'm interested in more than writing code for its own sake. Over time, I want to learn how to identify a problem people actually face, design a practical solution, and build something that can grow beyond a class assignment. That's also what draws me toward entrepreneurship.

Where this leads

I don't need to pretend I'm already an experienced engineer. I want to show how I'm becoming one.
